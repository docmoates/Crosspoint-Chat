OpenRouter takes a single reasoning object with either effort or max_tokens, and streams the reasoning text back as delta.reasoning1. Usage arrives in the last chunk when you set stream_options.include_usage3. Here is the adapter:

 openrouter.ts export async function* stream(req: ChatRequest): AsyncIterable<ChatEvent> {
  const res = await fetch(`${BASE}/chat/completions`, {
    method: "POST",
    headers: { Authorization: `Bearer ${key}`, "Content-Type": "application/json" },
    body: JSON.stringify({
      model: req.model, messages: toOpenAI(req.messages), tools: req.tools,
      stream: true, stream_options: { include_usage: true },
      reasoning: req.effort ? { effort: req.effort } : undefined,
    }),
  });
  for await (const chunk of sse(res.body)) {
    const d = chunk.choices?.[0]?.delta;
    if (d?.reasoning) yield { type: "thinking", text: d.reasoning };
    if (d?.content)   yield { type: "text", text: d.content };
    if (d?.tool_calls) yield* bufferToolCalls(d.tool_calls);
    if (chunk.usage)  yield { type: "usage", ...chunk.usage, cost: chunk.usage.cost };
  }
  yield { type: "done" };
}

Vector store decision

Recommendation. Use pgvector with an HNSW index on the existing Postgres instance. For a single user with tens of thousands of chunks, query latency stays well under 50 ms and nothing new has to be deployed or backed up.

When to revisit. If the corpus passes about one million chunks, or if filtered search by project and file type becomes slow, Qdrant is the move. Its filtering and quantization are better at that scale.

Migration cost. Low. Embeddings are stored with their source chunk id, so re-indexing into another store is a batch job, not a rewrite.
